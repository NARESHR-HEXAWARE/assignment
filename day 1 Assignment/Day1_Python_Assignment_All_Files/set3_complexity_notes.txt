SET 3 — HOSPITAL APPOINTMENT DESK: COMPLEXITY

1. Patient lookup: linear search O(n), binary search O(log n) on a list sorted
   by patientId. O(1) search extra space. Benchmark: 1,000 lookups over 20,000
   generated patient records. Real wall times depend on the machine.
2. Appointment sorting: priority is higher urgency first, then earlier arrival.
   Selection sort O(n^2) time, O(1) extra space after copying input, at most
   n-1 swaps. Quicksort average O(n log n), worst O(n^2); recursive stack
   average O(log n), worst O(n). Both report actual swap counts and times.
   Sample typed selection trace (urgency only, distinct arrivals):
   input [2,5,1,4] => pass 1 [5,2,1,4] => pass 2 [5,4,1,2]
   => pass 3 [5,4,2,1].
   Quicksort can have more swaps yet run faster due to fewer comparisons.
3. Duplicate booking: hash set of (patientId, slot), O(n) expected total time,
   O(n) extra space; scanning the previous list for every record costs O(n^2).
4. Queue: walk-in tokens FIFO, O(1) amortized enqueue/dequeue. Stack: recent
   patients LIFO, O(1) amortized push/pop. Both implemented from scratch.
5. Non-overlapping appointment scheduling: intervals are [start, end) and
   each appointment counts as one regardless of duration. DP with binary
   search on sorted finishing times is O(n log n) time, O(n) space. Earliest
   finish time greedy is ALSO optimal for maximizing the COUNT of unweighted
   non-overlapping intervals. Thus a claim that DP must beat greedy for this
   exact objective would be incorrect. DP becomes useful if appointments
   carry different weights/priorities or other constraints. In that case
   replace the +1 in the recurrence with the appointment's weight.
